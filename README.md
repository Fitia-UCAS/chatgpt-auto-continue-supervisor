# ChatGPT 自动续作监督器 v1.0.30

## v1.0.30

- 没有生成文件的助手回复现在始终会按等待时间发送续作指令，不再受严格下载模式影响。
- 严格下载模式只在“确实发现文件、但下载尚未确认”时等待；它不再把普通文字回复误当成缺失文件。
- 无文件续作使用独立状态，监督过程中切换严格下载模式也不会取消已经排队的无文件续作。
- 选项和控制台文案已同步说明上述规则。

## v1.0.29

- Edge 原生下载列表不再只靠点击前的 4.2 秒短脉冲抑制；现在会在整批文件下载期间持续关闭，批次完成并稳定后才恢复。
- 下载任务创建后会立即、延迟 120ms、延迟 400ms 三次补关，处理 Edge 原生下载浮层晚于下载事件挂载、关完又重新出现的时序竞争。
- `downloads.setUiOptions()` 改用带回调和超时的结果确认；权限缺失、浏览器不支持或调用失败会写入监督日志，不再静默吞掉。
- 下载 UI 的关闭租约会保存在浏览器会话中，并由独立恢复定时器兜底；即使 Edge 暂停或重启扩展后台，批次结束后也会确认恢复下载按钮，临时失败则自动重试。
- 真实的 Windows 鼠标点击不属于网页扩展能力：网页 `.click()` 只能点击 ChatGPT 页面，无法命中 Edge 顶栏。当前实现直接调用浏览器的下载 UI 关闭接口，不移动鼠标，也不会误点页面内容。

## v1.0.28

- 使用浏览器正式的 `downloads.setUiOptions()` 能力，在监督器自动点击下载前短暂隐藏 Edge/Chrome 原生下载 UI，阻止右上角下载列表自动弹出。
- 每次抑制仅维持几秒并自动恢复；只影响自动下载触发窗口，不会清除下载记录，也不会永久隐藏浏览器下载功能。
- 若浏览器版本不支持该 API，会静默回退，原有下载和 ChatGPT 页面内预览清理不受影响。

浏览器 API 的作用域是当前 Edge/Chrome 配置文件的所有窗口，因此自动点击后的短暂几秒内，其他同配置文件窗口的下载图标也会一起隐藏；恢复后可以照常使用。

## v1.0.27

- 同一文件同时出现正文“下载”入口和文件卡片时，优先使用可点击的命名文件卡片及其行内下载按钮。
- 自动点击文件入口所打开的 ChatGPT 右侧预览，会在下载成功、失败或超时后统一关闭；原先由用户打开且未被本次操作改变的预览会保留。
- 兼容预览延迟挂载、工具栏重绘和无文字标签关闭按钮，避免多文件处理时沿用上一项的预览。

说明：ChatGPT 页面内预览仍由内容脚本负责关闭；Edge/Chrome 原生“下载”列表则由 v1.0.28 新增的浏览器级下载 UI 权限负责抑制。

## v1.0.26

- 多文件卡片出现“还有 N 个 / N more”时，先自动展开折叠项，再重新扫描完整文件列表。
- 一条回复中的文件逐项处理；部分文件未确认下载时，会只对遗漏项再补试一轮。
- 下载目标仍采用安全上限 12 个，并非最多只能下载 2 个。

## v1.0.25

- 修复自定义助手具体会话（`/g/.../c/...`）被误判为“不是具体对话”，导致“监督当前页”无法启动。
- 会话消息识别兼容新版 ChatGPT 的多种角色和对话轮次标记，不再只依赖 `data-message-author-role`。
- ChatGPT 正在思考或临时重绘消息节点时，仍可依据具体会话地址和主对话区域安全启动监督。

本版继续保留 v1.0.19 的稳态滚动修复，并调整 v1.0.20 的下载/续作规则与弹窗布局。

## v1.0.24

- 四个功能页统一高度：以“当前页”的自然高度为基准。
- 控制台和多页面列表只在各自内部滚动，不再改变插件外框高度。

- 修复弹窗固定 520px 高度导致“当前页”下方出现大块空白。
- 当前页、选项页改为随内容自动收缩；多页面与控制台只在各自内容区内部滚动。
- 控制台保留独立固定工作区，不再影响其他页签的弹窗高度。

## 更新方式

在 `chrome://extensions/` 中重新加载扩展，然后刷新已经打开并需要监督的 ChatGPT 对话页。


## v1.0.24 下载检测修正
- 浏览器下载事件短暂延迟时，不再立即永久判定为“未确认”。
- 初次确认未命中时，后台并行补查 15 秒；补查不会拖延“未确认下载也继续”的续作计时。
- 下载记录匹配同时考虑文件名、URL、finalUrl 与 referrer，并容忍浏览器自动重命名。
